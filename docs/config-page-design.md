# 设置页的设计（三栏工作台 + 模型配置弹窗）

这份文档说的是**界面上的「设置」长什么样、每一项存在哪、什么时候生效**。
「最近改了什么」看 `CHANGELOG.md`；「还没做的」看 `docs/backlog.md`。

入口是左栏品牌行那颗齿轮（`frontend/src/components/settings/SettingsPage.vue`），`Esc` 或左上角返回回到聊天。
切页时聊天区用 `v-show` 藏在原地（不卸 DOM：正在跑的流还在往 App 的状态里写）；
「在哪一页」记在 URL 的 hash 上（`#settings/basic|look|models`，见 `frontend/src/lib/viewState.ts`），
所以**刷新之后还在原来那一页**。

## 一、左菜单四栏

| 栏目 | 里面是什么 | 存在哪 | 生效时机 |
|------|-----------|--------|---------|
| **基本设置** | 界面偏好（默认右栏标签 / 恢复默认布局）、代码缓存配置、上下文窗口配置 | 界面偏好在本机；其余两格在**后端库** | 界面偏好**立刻**；后端那两格**保存即生效**（不用重启） |
| **外观** | 主题（浅色 / 深色 / 跟随系统）、代码字号 12–16、对话列宽（紧凑 / 标准 / 宽） | 本机 | **立刻** |
| **模型配置** | 按**智能体**配的模型连接 | 后端库 | **下一轮**生效（见第六节） |
| **提供商** | 目录本身：显示名 / 默认地址 / 清单路径 / 鉴权头 / 分组排序 / 启停 | 后端库 | **刷新界面即生效**（目录是每条请求现读库的） |

## 二、基本设置

### 界面（本机，立刻生效）

| 项 | 说明 |
|----|------|
| 默认打开的右栏标签 | 刷新/新开页面时右栏停在哪个标签（代码 / 记忆 / PR / 日志 / Token） |
| 恢复默认布局 | 两个栏宽 + 收起状态 + 退出右栏全屏，清回默认 |

存在 `localStorage`（`ui.panelTab` / `ui.sidebar.*` / `ui.right.*`，见 `frontend/src/lib/prefs.ts` 与
`splitter.ts`）—— 本机单人的显示偏好，后端没有「用户设置」表，为它加表加迁移不划算。

### 代码缓存配置（后端库，保存即生效）

| 项 | 键 | 说明 |
|----|----|------|
| 代码缓存路径 | `repo_view_dir` | 右栏「代码」面板那份**本地裸仓**放哪（默认 `~/.ai-coding-harness/repo_cache`）；换路径等于换一份缓存，旧目录里的克隆不会跟着搬 |
| 默认分支（Gitee / GitHub） | `gitee_base_branch` / `github_base_branch` | 代码面板默认打开哪支。**留空＝按远程探测**（推荐）；填了就以它为准，填错会打开一个不存在的分支 |

### 上下文窗口配置（后端库，保存即生效）

**只有两条阈值**：告警线（默认 0.6，环图开始变色）与危险线（默认 0.8，给一句「可能触发压缩」）。
窗口长度本身**不在这里配** —— 它是**模型**的属性，按模型查（见第五节）。

平时**不做常规 40k 剪裁**。到达压缩线时，压缩中间件会先做一次**应急工具裁剪**（只保留
当前这一步的工具返回），剪完低于线就本轮不摘要，仍高于才继续压。它跟随
`CONTEXT_TRIM_TOOL_RESULTS` 总开关，不是单独一项配置。

## 三、模型配置

### 3.1 行是**智能体**，不是供应商

界面上有这些行（顺序即 `config.MODEL_AGENT_ROWS`）：

| 行（键） | 中文名 | 谁在用它 |
|---------|--------|---------|
| `qa` | 问答 | qa 形态的主控 |
| `analysis` | 分析 | analysis 形态的主控 |
| `plan` | 方案 | plan 形态的主控 + **编码那组的 planner**（复用） |
| `review` | 审查 | review 形态的主控 + **编码那组的 reviewer**（复用） |
| `coding` | **编码主控** | coding 形态的主控（orchestrate） |
| `coder` | **编码** | 编码那组的 coder 子智能体 |
| `unified` | 统一模型 | **只兜底那些没配的行**（配了的行按自己的走，2026-10-15 用户口径） |
| `fallback` | 兜底模型 | 主模型重试耗尽后换它再试 |
| `jev` | **意图识别（JEV）** | 意图判定选了 JEV 时那一侧；**供应商锁死 `typesafe`** |
| `classifier` | 意图识别（大模型） | 意图分类那一关用的模型 |

**「编码」是一主三从**（2026-10-14 用户口径）：主控与 coder **各占一行**，planner / reviewer
**复用「方案」「审查」两行** —— 四个角色都有出处，但只有主控与编码要配。
映射在 `agent/llm._AGENT_KEY`（守卫测试逐个角色钉住）。

**分栏与角色归属由后端下发**（2026-10-15）：每行带 `section`（各智能体 / 全局 / 意图识别）与
`roles`，快照里另有 `coding_group`（4 个角色 → 落在哪一行、是不是复用）—— 前端不再硬编码行名，
后端加一行不会再在界面上静默消失。

### 3.2 列表里一行是**两段**：主行「名字 + 配置按钮」，次行**生效值**

**没有「出厂默认」**（2026-10-15 用户口径：干掉它）：行内没配就是空的（`source=unset`），
不再回填 `.env` 那套值，也不再显示「已配置 / 出厂默认」那类 chip。要回答「现在到底用什么」，
看每行下面那行**生效值**（后端 `llm.effective_for` 解析）：

| 生效值 | 含义 |
|--------|------|
| `模型名 · 窗口 128K` | 这一行自己配的（`source=row`） |
| `模型名 · 窗口 1M · 本行没配，走「统一模型」` | 这一行没配，靠「统一模型」兜底 |
| `未配置：用到这个角色的那一轮会报错` | 没配（`source=unset`）—— 不再有 `.env` 兜底 |

点「配置」打开弹窗，**分三类**：

| 类 | 内容 |
|----|------|
| 供应商 | 分组下拉（国内 / 海外）。**一换供应商，配置项全部清空**，并把新那家的默认地址带出来 |
| base_url / api_key | 两格 + 「测试连接」（缺地址或 key 时置灰并写明缺哪样；探测结果回显在这一类下面） |
| 模型 / 窗口大小 | 模型名（带候选下拉，**必填**，红 `*`）+ 「刷新清单」+ 窗口。窗口那一格回显**真值**（后端解析到的：行内手填 / 按模型查），手改过才写库；查不到就留空 |

**保存按钮在弹窗内部**（用户口径）：只提交**这一行**改过的字段，成功后关掉弹窗，
落库即**下一轮生效**。报错**就地显示在弹窗里**（写页面顶部那条会被遮罩挡住，看不见），
按 `Esc` 只关弹窗（不会把整页和草稿一起关掉）。意图识别的二选一是个分段控件、
没有弹窗可放保存按钮，所以**改完当场存**。

### 3.3 意图识别：**严格二选一**

分段控件选「JEV」或「大模型」，两侧各有一行配置（JEV 那一行的供应商锁死 `typesafe`、
界面不可改）。**选了哪一侧就只走哪一侧**：那一侧没配齐 / 判不出来 → 直接落**关键字口径**，
不借另一侧（2026-10-15 用户口径）。JEV 没配齐时界面上给一句提示。

顺带几条（2026-10-15 用户口径）：

- 窗口那一格按 `1M` / `128K` 显示（存库仍是 tokens，进制 1024，见 `frontend/src/lib/modelWindow.ts`），
  且**只回显真值** —— 后端解析出来的窗口带一个来源（`row` 行内手填 / `model` 按模型查到 /
  `fallback` 我们的保守值），界面只显示前两种：`fallback` 不是厂商给的数，回显出来会让人以为
  查到了（用户原话：「这个 128K 从哪来」）。查不到就**留空**，要准就手填或点「刷新清单」。
- 它是**回显**（`window_auto`）：没手改就不写库；「测试连接」读到的窗口也只作显示
  （那个值取自清单里第一个带窗口的模型，未必是你选的那个）。
- 必填只用一个红 `*` 表示（模型名总是必填；JEV 那一行的 base_url / api_key 也必填），
  不写解释性小字；窗口那一格没有任何提示文字。
- **换供应商 = 下面的值全部清空**（含 key）：界面清掉只是草稿，保存时会送空串把库里那一把也清掉。
  专门的「清除 key」按钮因此撤掉了 —— 换一家就够了。
- **点弹窗外面不关**（误点一下就得重配一遍）；要关按 X 或 `Esc`。

### 3.4 「测试连接」的门槛只有两样

**`base_url` 有值 + 有可用 key**（库里那把或界面上刚填的）。目录行怎么写都不拦 ——
`is_dynamic_model_list` 只是「这家官方有没有 /models」的标注，`/probe` 一定会发请求，
拉不到就回错误原文（不是 500）；**不再回内置候选**（那份静态名单 2026-10-15 已删）。

### 3.5 供应商的模型清单：**点了刷新才拉**

「刷新清单」按钮（在弹窗第三类里）＝ `POST /model-config/providers/{p}/models/refresh`：
拿这家的默认地址去调它的清单接口，结果**逐条写进模型详情表**（非文本模型也落表并标类型）。
**不轮询、保存时也不刷**（用户口径）。key **借用现有 agent 行的**（一行都没配就看 `.env` 里这家的
凭据）—— 不新增第二处凭据存放点。

两条克制的规则：刷新**不删**本地多出来的行（可能是老模型或别处在用）；
入口没回窗口时（实测 GLM 的入口就不回）**不覆盖**已有的非 0 窗口值。

## 四、提供商（第 4 栏）：目录本身在这里改

**为什么有这一栏**（2026-10-15 用户口径 b）：目录以前只能改库、或改 `config/model_providers.toml`
再 `POST /model-config/providers/reload` 对齐；而「清单路径」「鉴权头」这两格只有真机试过才
知道怎么填（GLM 要多一层 `/v1`、qwen 的清单在另一个根下面、有的网关用 `x-api-key`）——
让用户手改库不对。目录本来就是**每条请求现读库**，所以这里改完**刷新界面即生效**，连重启都不用。

| 界面上的格子 | 落在哪一列 | 说明 |
|-------------|-----------|------|
| 键 | `provider` | **唯一**、不可改：模型行与 agent 行都按它挂（外键目标）；新增时由用户填，只收 `a-z 0-9 _ -` |
| 显示名 / 分组 / 排序 | `display_name` / `ui_group` / `sort_order` | 下拉里的样子与顺序（分组同名的排在一起） |
| 默认地址 | `default_base_url` | 选中这家时带进弹窗的那个地址（可改，不强制） |
| 清单路径 | `models_path` | 拼在默认地址后面；**写成 `http` 开头就整段用它**（qwen 靠这个） |
| 鉴权头 / 前缀 | `auth_header` / `auth_prefix` | 默认 `Authorization` + `Bearer `；有的网关是 `x-api-key`（前缀留空） |
| 状态 | `status` | 停用的家**不进下拉**，但**在这一栏里看得见**、能改回来 |
| 官方有 `/models`？ | `is_dynamic_model_list` | 只是标注；「测试连接」不看它 |

两条刻意的做法：

- **不删除，只停用**：`provider` 是模型行（`provider_models.provider`）与 agent 行的外键目标，
  删一行会牵出「那些行怎么办」；要下架就停用。
- **整行覆盖**（与 DAO 现有语义一致）：界面提交整行，不留「老值赖着」的坑。

写接口末尾会**当场刷一次** `Settings.providers`（那份只在读库失败时兜底、以及给「按地址反推
供应商」用），所以连它也不用等重启。种子文件从此只是**新库的初始快照 + 参考**，
「改目录」这件事一律在界面上做。

## 五、窗口与候选：两处解析口径

### 5.1 上下文窗口（`llm.resolve_window`）

| 顺序 | 来源 | 为什么在这个位置 |
|------|------|----------------|
| ① | 那一行**显式填的**窗口 | 单点覆盖，专治特例 |
| ② | 按 **`(供应商, 模型)`** 查模型详情表 | 窗口是**模型**的属性：同一家 `glm-5.3` 是 1M、`glm-4.6` 是 128k |
| ③ | 按**模型名**全局再查一次 | 自建网关（`custom`）地址对不上任何一家，但同名模型的窗口一样 |
| ④ | 兜底值（默认 128k，可在设置页改） | 读不到就用保守值：偏小只是早一点触发压缩 |

`.env` 的 `*_CONTEXT_WINDOW`（逐家那几格）**已作废**（2026-10-15）。这一行没配模型时**不报错**，
直接给保守值 —— 窗口只是提示与压缩线，真正拦下来的是「这一行没配模型」（见 3.2）。

### 5.2 「供应商」那一栏怎么定（`config.provider_key_for`）

按 `base_url` 反推：命中目录里某家的默认地址就是它，否则是 `custom`。**纯界面提示**，
不参与任何解析 —— 模型真正用哪套连接由 `base_url + 模型 + key` 决定。
**JEV 那一行例外**：供应商锁死 `typesafe`（`config.MODEL_AGENT_PROVIDER_LOCK`），
界面上那一栏置灰不可改。

### 5.3 模型名候选（弹窗里那个下拉）

刚拉到的实时清单（最准）→ 这家**已登记的文本模型**（模型详情表里 `model_type=chat` 且启用的）
→ 种子文件里那串名字。

### 5.4 清单接口返回的两种形状（2026-10-15）

「测试连接」与「刷新清单」拉的是同一件事：那家的 `/models`（路径来自目录行的 `models_path`，
**可以写绝对地址** —— qwen 的清单在 `https://dashscope.aliyuncs.com/api/v1/models`，不在它
兼容入口那个根下面）。返回形状认两种：

| 形状 | 谁是这样的 | 名字 / 窗口在哪 |
|------|-----------|----------------|
| `{"data": [{"id": …}]}` | deepseek / glm / kimi / openai… | 平铺在条目上（窗口键见下） |
| `{"output": {"models": [{"model_info": {…}}]}}` | qwen 原生入口 | **名字与窗口都埋在 `model_info` 里** |

窗口只认这四个键（任意层级里找，同一层按这个顺序）：`context_length`（glm / kimi 实测）、
`context_window`（deepseek 实测 / qwen）、`max_context_length`、`max_input_tokens`；
值可以是数字也可以是数字字符串。**openai 那条接口什么都不回**（实测），
那几家的窗口只能手填。

实测路径（2026-10-15）：glm 是 `…/api/paas/v4/v1/models`（**多一层 `/v1`** ——
`…/api/paas/v4/models` 只回名字、不带窗口）；qwen 是绝对地址
`https://dashscope.aliyuncs.com/api/v1/models`；deepseek / kimi 用默认的 `/models` 就行。

## 六、存在哪、什么时候生效

| 数据 | 表 / 位置 | 生效时机 |
|------|----------|---------|
| 按智能体的模型连接 | 表 `model_endpoints` | 保存后**下一轮**：主智能体**每轮现建、不缓存**，保存时当场刷新内存那份 `Settings`；**正在跑的那一轮不换模型** |
| 提供商目录 | 表 `model_providers` | **每条请求现读库**：改库 + 刷新界面就生效，不用重启 |
| 模型详情（名字 / 类型 / 窗口） | 表 `provider_models` | 启动时读进内存镜像（`Settings.provider_models`），刷新/手改之后当场换 |
| 运行期配置（缓存路径 / 默认分支 / 阈值） | 表 `app_settings` | 保存时**赋回 `Settings` 实例**，`GET` 时也会重新落一遍（直接改库也能生效） |
| 本机显示偏好 | `localStorage` | 立刻 |

**没有出厂默认**（2026-10-15）：`.env` 里那几组模型凭据 / 窗口已作废，只留 `GLM_API_KEY` /
`GLM_BASE_URL`（web 搜索用）。**一行没配 = 这一行没有模型可用**，用到它的角色当场报错
（`tests/test_model_config.py::TestResolution` 与 `tests/test_llm_config.py` 钉着）；
`unified` 只兜底**没配**的行（配了的行按自己的走）。

## 七、接口一览

| 方法 | 路径 | 干什么 |
|------|------|-------|
| GET / PUT | `/model-config` | 读 / 写按智能体的模型连接（留空＝不改；`api_key` 只回打码值） |
| DELETE | `/model-config/{agent}` | 清空某一行（界面上叫「清空这一行」） |
| POST | `/model-config/probe` | 「测试连接」：拉一次那家的清单（不改库） |
| GET | `/model-config/providers` | **提供商目录全量（含停用）** —— 第 4 栏那个列表用它 |
| PUT | `/model-config/providers/{p}` | **写一行提供商目录**（整行覆盖；键在 URL 里、不可改） |
| GET | `/model-config/providers/{p}/models` | 这家的模型清单 |
| POST | `/model-config/providers/{p}/models/refresh` | **刷新模型清单**并落表（可带 `?base_url=` ＝ 这一行手填的地址） |
| PUT | `/model-config/providers/{p}/models` | 手填 / 手改一个模型（窗口 / 类型 / 启停） |
| POST | `/model-config/providers/reload` | 按种子文件**对齐**目录（同名行覆盖，多出来的不动） |
| GET / PUT | `/app-settings` | 运行期配置（代码缓存 / 阈值） |

**新增后端路由前缀要同步加进 `frontend/vite.config.ts` 的 `server.proxy`** —— 漏了的现象是
「点开界面就报错，而 curl 后端 200」。

## 八、几个刻意的决定

- **配置的轴是智能体，不是供应商**：同一个供应商下不同模型、不同角色本来就该分开配。
- **没有出厂默认**（2026-10-15 用户口径）：回落会让「界面上什么都没配」也能跑，用户根本看不出
  自己在用哪个模型 —— 所以一行没配就报错，并在界面上给出**生效值**（现在真的用谁）。
- **窗口按模型查，不按供应商**：按家取值时，同一家里两个智能体配不同模型会拿到同一个窗口，
  压缩线被推到错的地方（请求早在真窗口之外就报错）。
- **模型清单只在点按钮时拉**：轮询会白打接口，而清单本身变得很慢也没关系。
- **key 只借不新增**：刷新用 agent 行里已有的那把，凭据存放点保持一处。
- **只存文件清单、不存 diff 正文**（聊天那条「改了什么」）：记录不该被几兆的 diff 撑大。
- **不引路由库、不引 UI 组件库**：两个页面用 hash，弹窗复用既有的 `.field/.input/.btn` 与设计令牌。
- **报错就地显示**：弹窗开着的时候页面顶部那条被遮罩挡住 —— 保存 / 刷新的失败得写在弹窗里。
- **换供应商就清掉旧 key**：界面清空只是草稿，保存时得送空串才真的清（「留空＝不改」的反面）。

## 九、界面上**故意**没有的东西

这些东西在 `.env` 里有效，但**不上界面**（用户口径或成本考虑）：

- 五家供应商的窗口值（`*_CONTEXT_WINDOW`）—— 窗口按模型查，逐家配已经是旧口径；
- 兜底窗口（`FALLBACK_CONTEXT_WINDOW`）—— 代码默认 128k，需要时走行内手填；
- 沙箱镜像加速地址 / Maven 镜像 —— 用户明确不用；
- 关键词、空转刹车、递归上限这类**调参**，以及沙箱 / 数据库 / Redis 的运维参数；
- 模型清单的**删除**与批量停用（接口留了单条 upsert，界面只做刷新与手改窗口）。
