# 删除与迭代计划模板

> 红线：本清单**只用于输出计划**，不执行删除。审查流程全程只读，任何删除动作都要等用户另行确认。

## 优先级

- **P0**：必须立即删除（安全风险、显著成本、阻塞其他工作）
- **P1**：本次迭代内删除
- **P2**：待办 / 下个迭代

---

## 现在就能删

### 项：[名称/描述]

| 字段 | 内容 |
|---|---|
| **位置** | `path/to/file.py:行号` |
| **理由** | 为什么应该删 |
| **证据** | 无引用、feature flag 已关、API 已废弃 |
| **影响** | 无 / 低 —— 没有活跃使用方 |
| **删除步骤** | 1. 删代码 2. 删测试 3. 删配置 |
| **验证方式** | 跑测试、确认无运行时错误、观察日志 |

---

## 需要计划再删

### 项：[名称/描述]

| 字段 | 内容 |
|---|---|
| **位置** | `path/to/file.py:行号` |
| **为什么缓** | 仍有使用方、需要迁移、需要相关方签字 |
| **前置条件** | flag 关闭满 2 周、埋点显示使用量为 0 |
| **破坏性变更** | 列出 API/契约层面的变化 |
| **迁移方案** | 使用方如何迁移的步骤 |
| **时间点** | 目标日期或迭代 |
| **负责人** | 对应的人/团队 |
| **验证指标** | 确认可安全删除的依据（错误率、调用量） |
| **回滚方案** | 出问题时如何恢复 |

## 删除前检查表

- [ ] 已全仓搜索所有引用（`rg`、`grep`）
- [ ] 已排查动态/反射式调用
- [ ] 已确认没有外部使用方（API、SDK、文档）
- [ ] 已核对 feature flag 埋点（如适用）
- [ ] 测试已更新/删除
- [ ] 文档已更新
- [ ] 已通知相关方（共享代码时）
