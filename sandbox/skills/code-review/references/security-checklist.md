# 安全与可靠性清单

## 输入/输出安全

- **XSS**：不安全的 HTML 注入、`innerHTML` 赋值、未转义的模板、`dangerouslySetInnerHTML`
- **注入**：字符串拼接或模板串构造出的 SQL/NoSQL/命令/GraphQL 注入
- **SSRF**：用户可控的 URL 未经白名单校验就打到内网服务
- **路径穿越**：用户输入直接进文件路径、未做净化（`..` 攻击）
- **原型污染**：Python 侧对应的是不受控的 `**kwargs` 展开、`setattr` 覆盖对象属性，或反序列化不可信数据

## 认证与鉴权（AuthN/AuthZ）

- 读写操作缺少租户或属主校验
- 新增接口没有鉴权守卫或 RBAC 强制
- 信任客户端传来的角色/标志位/ID
- 越权访问（IDOR：直接改了对象 ID 就能读别人的数据）
- 会话固定攻击或会话管理薄弱

## JWT 与令牌安全

- 算法混淆攻击（该用 RS256 却接受 `none` 或 HS256）
- 密钥弱或硬编码
- 缺过期时间（`exp`）或不校验 `exp`
- JWT 载荷里放敏感数据（JWT 是 base64，不是加密）
- 不校验 `iss`（签发方）或 `aud`（受众）

## 密钥与个人信息

- 代码/配置/日志里出现 API key、令牌、口令
- 密钥进了 git 历史，或环境变量被暴露给客户端
- 过度记录个人信息或敏感载荷
- 错误信息里没有做脱敏

## 供应链与依赖

- 依赖不锁版本，允许恶意更新
- 依赖混淆（私有包名被公共源上的同名包抢占）
- 从未受信来源或 CDN 引入代码且不做完整性校验
- 依赖版本过旧、存在已知 CVE

## CORS 与安全响应头

- CORS 过于宽松（`Access-Control-Allow-Origin: *` 同时带 credentials）
- 缺安全头（CSP、X-Frame-Options、X-Content-Type-Options）
- 暴露内部响应头或堆栈信息

## 运行时风险

- 无界循环、无界递归、超大内存缓冲
- 外部调用缺超时、重试或限流
- 请求路径上有阻塞操作（异步上下文里做同步 IO）
- 资源耗尽（文件句柄、连接、内存）
- ReDoS（正则拒绝服务）

## 密码学

- 弱算法（把 MD5、SHA1 用于安全目的）
- 硬编码的 IV 或 salt
- 只加密不认证（ECB 模式、无 HMAC）
- 密钥长度不足

## 竞态条件

竞态是隐蔽的缺陷，会造成偶发失败和安全问题，要重点看：

### 共享状态访问

- 多线程/协程/异步任务访问共享变量却没有任何同步
- 全局状态或单例被并发修改
- 懒初始化没有正确的加锁（双重检查锁的坑）
- 在并发场景里用了非线程安全的容器

### 先检查后执行（TOCTOU）

- `if (存在) then 使用` 这类模式，中间没有原子操作
- `if (有权限) then 执行`，而权限可能在中间变化
- 先判断文件是否存在、再对文件操作
- 先查余额、再扣减（资金类操作）
- 先查库存、再下单

### 数据库并发

- 缺乐观锁（`version` 列、`updated_at` 校验）
- 缺悲观锁（`SELECT ... FOR UPDATE`）
- 读-改-写没有事务隔离
- 计数器自增不是原子操作（应写成 `UPDATE ... SET count = count + 1`）
- 并发插入触发唯一约束冲突

### 分布式场景

- 共享资源没有分布式锁
- 主节点选举存在竞态
- 缓存失效竞态（写完立刻读到的还是旧值）
- 依赖事件顺序却没有做序列化保证
- 集群操作出现脑裂

### 典型的危险写法

```python
# 危险：先检查后创建（TOCTOU）
if not exists(key):
    create(key)

# 危险：读-改-写
value = get(key)
value += 1
set(key, value)

# 危险：先判断后扣减
if user.balance >= amount:
    user.balance -= amount
```

### 该问的问题

- 「两个请求同时打到这里会发生什么？」
- 「这个操作是原子的吗？会不会被打断？」
- 「这段代码访问了哪些共享状态？」
- 「高并发下它的行为是什么？」

## 数据完整性

- 缺事务、只写了半截、状态更新不一致
- 落库前校验薄弱（类型强转的坑）
- 可重试的操作没有幂等
- 并发修改导致更新丢失
