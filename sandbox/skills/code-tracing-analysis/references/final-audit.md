# 交付前审计：用否定式检查推翻草稿

审计的不是格式齐不齐，而是正文里有没有下列**可观察的缺失**。出现任一项即判未完成，回对应步骤补齐；
不许靠加「已确认 / 已闭合 / 已检查」这类形容词掩盖。

## 收口门（行为 / 流程类问题必过）

- **停在 helper**：结论止于一个中间函数，没连到返回、状态提交或副作用 → 回追踪闭合主链。
- **单向追踪**：只有正向 entry→result 或只有反向 result→caller，两侧没在某一跳相遇核对 → 补双向追踪。
- **关键跳塌缩**：多个关键跳压成一句话，缺实际调用表达式或分派条件 → 补链账本：
  `起点 path:symbol:line → [实际调用表达式 / 分派条件] → 终点 path:symbol:line`。
- **竞争解释没搜**：存在同名实现、动态分派或多候选风险时，正文要留下**实际执行过的搜索产物**
  （查询与结果，含「该范围内未见」）；浮现 ≥2 个机制却只讲一个、不给判别动作 → 回反证。
- **保证空推导**：一致性、幂等、唯一、可靠等结论只由局部机制推出、没有端到端证据 → 降级措辞或补证据。
- **激活混用**：写了「线上在跑 / 已生效」却没有可复核的运行观测来源 → 降为 selected 或「静态可达」。

纯存在性、结构 / 归属问题不套链账本：用带搜索边界的主张或边界图收口。

## 交付审计

- 定位是否来自本轮实际读取：文件、symbol、行号是否真实存在；把真实文件说成用了它没有的机制
  （锁、反射、缓存、分派方式）同样判失败。
- 事实 / 推断 / 未知是否分层标了 confirmed / inferred / unknown / conflicted。
- 首屏顺序：范围与证据状态 → 直接答案 → 最短主链 → 未知与验证动作；点名阶段不得被相邻名称静默换题。
- 正文有没有「让我读取 / 接下来我会」这类过程话术，或停在表格中途的半截截断 —— 有即回炉。
- 声称「完整 / 全面」却没附「未检查范围」清单 → 删掉完整性用词或降级。

## 阻断与检查点

- 只在用户硬 deadline、需要新权限、平台硬限制或新增取证已不能产生独立答题证据时停止；
  受影响的主张标 `unknown`，首屏标 PARTIAL / BLOCKED，列未闭合主张、影响与最小解阻动作。
- 接近上下文硬限制时先写检查点（`/ai_coding/tmp/evidence-ledger.md`）：已闭合边及来源、未闭合边与
  竞争解释、已查与未查范围、下一条最有信息增益的查询。**检查点不是完成**，不许冒充闭合。
- 不得自设 token、耗时、篇幅上限去截断未闭合的决定性边；但平台真的断了就诚实交付 PARTIAL。
