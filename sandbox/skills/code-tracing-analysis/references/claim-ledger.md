# 证据账本与证据权限

写结论前先用这张表裁决「哪类材料能证明什么」；账本不替代读代码，只规定一句话凭什么进正文。

## 证据权限

| 来源 | 可以裁决 | 不能单独裁决 |
|---|---|---|
| 当前源码实现 | 直接表达的实现与静态关系 | 已装配、当前选中、线上激活、外部保证 |
| 构建 / 发布 / 宿主配置 | 直接表达的边界、装配或条件 | 没写出的运行事实、全部条件 |
| 来源完整的运行 artifact | 该版本、环境、调用与 workload 的观测 | 其他版本、环境或条件 |
| README / 设计文档 | 声明的约定与待核对的契约 | 当前可执行配置、运行事实 |
| issue / fixture / mock / 注释 / 目录名 / 未提交 diff | 该材料或候选存在 | 当前系统行为、外部契约、生产效果 |

## 定位与身份

- 用户点名的仓库、路径、符号、配置键先建身份卡：`repo@分支 | path | 字面 symbol / 配置键 | 已读范围`。
- 点名对象不可读或不存在 → 报 PARTIAL / BLOCKED，**不许改答相邻目录、同名实现或文档里的说法**。
- 精确的 path、symbol、flag、配置键、数字、枚举与固定顺序，必须有逐字声明或完整检索边界；给不出就删掉精确写法或降级。

## 四个状态

- `confirmed`：本轮直接读到实现且范围闭合；只有直接观察能拿它。
- `inferred`：写前提与证伪动作。
- `unknown`：写缺失的边与它对结论的影响。
- `conflicted`：写冲突范围与判别动作；先核对快照、环境与证据来源。
- 证据强度不按数量相加：多处注释、文档或同源索引重复同一说法，不能把推断投票成事实。

## 激活轴

| 阶段 | 最小证据 | 不能推出 |
|---|---|---|
| defined 已定义 | 当前快照里的实现或声明 | 已接入系统 |
| assembled 已装配 | 构造、注册、注入、订阅、导出或宿主加载关系 | 本次条件会选中 |
| selected 已选择 | 当前配置、参数、条件或调用路径指向它 | 已在某环境执行 |
| runtime_activated 运行时已激活 | 来源完整的运行观测（谁、怎么调、何时、何环境、何 workload、退出状态，均可复核） | 其他版本 / 环境 / workload 也会执行 |

缺某阶段就停在前一阶段并记录缺口；日志自称来自某环境、文件名带版本号，都不能补齐来源。

## 负向搜索与全称

- 负向搜索记录：查询、路径范围、名称变体、排除项与快照；无结果只表示**该范围内未发现**。
- 「所有 / 始终 / 绝不 / 保证 / 原子 / 自动恢复」必须有分支覆盖表：实际实现、条件路由、批次 / 循环、提前返回与外部边界的成功、失败、部分完成都绑了证据；任一格未知就缩小主张或标 `unknown`。
